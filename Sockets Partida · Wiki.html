      🔌 Guía de Integración WebSocket — Frontend

      Referencia técnica completa para el equipo de Frontend
      Stack: Socket.IO v4 · Servidor: http://localhost:3000

      Índice

      1. Flujo de Conexión: Paso a Paso
      2. Autenticación

      4. Partida (Game)

      1. Flujo de Conexión: Paso a Paso

      Antes de conectar al WebSocket hay que pasar siempre por los endpoints HTTP de la API REST para obtener el wsToken. A continuación se muestra el flujo completo ordenado:

      [Pantalla de Inicio]
        │
        ▼ (1) POST /api/auth/login  →  jwtToken del usuario
        │
[Pantalla de Lista de Salas]
        │
        ├─► (2a) Si CREA sala:  POST /api/lobby              →  lobbyCode + wsToken
        │
        └─► (2b) Si SE UNE:     POST /api/lobby/:code/join   →  wsToken
        │
[Pantalla de Lobby - Sala de Espera]
        │
        ▼ (3) io.connect con wsToken
        │
        ▼ (4) socket.emit('client:lobby:join')  ← ¡OBLIGATORIO!
        │
        │    El servidor emite ──► server:lobby:state_updated (a todos)
        │
[El host pulsa "Iniciar Partida"]
        │
        ▼ (5) socket.emit('client:lobby:start')
        │
        │    El servidor emite ──► game:started (a todos) ← navegar al tablero
        │                   ├──► server:game:started (a todos) ← estado completo
        │                   └──► server:game:private_hand (a cada jugador)
        │
[Pantalla de Juego]
        │
        ▼ ... acciones de juego (client:game:action) ...
        │
[Alguien alcanza 42 pts → phase = FINISHED]
        │
        ▼ (6) socket.emit('client:game:end', { lobbyCode })
        │
        │    El servidor emite ──► server:game:ended (a todos) ← ranking final
        │                   └──► server:economy:wallet_updated (a cada jugador)
        │
[Pantalla de Resultados]

      2. Autenticación

      2.1 Obtención del wsToken

      Un wsToken es un JWT especial distinto al JWT de login. Se obtiene de:

      Acción Endpoint Respuesta
      Crear sala POST /api/lobby { wsToken, lobbyCode }
      Unirse a sala POST /api/lobby/:lobbyCode/join { wsToken, lobbyCode }

      El wsToken tiene una vigencia de 5 minutos. Si expira antes de conectarse, el usuario deberá volver a hacer el request HTTP.

      2.2 Conectar al WebSocket

      import { io } from 'socket.io-client';

const socket = io('http://localhost:3000', {
  auth: {
    token: wsToken, // ← JWT obtenido del endpoint REST
  },
  transports: ['websocket'], // Forzar WebSocket puro (sin polling)
});

      Important

      El wsToken debe ir en auth.token del handshake, no en los headers. Si el token está ausente, expirado o es inválido, la conexión es rechazada directamente antes de llegar a ningún handler.

      2.3 Payload del JWT (para referencia)

      El servidor extrae internamente del token:

      Campo Tipo Descripción
      id string ID del usuario — formato "u_123"
      username string Nombre de usuario visible
      lobbyCode string Código de sala de 4 caracteres

      No necesitas decodificar el token en el Frontend. El servidor usa estos datos para identificar al usuario en cada evento.

      3. Sala de Espera (Lobby)

      3.1 Entrar al Lobby — client:lobby:join

      Important

      Este es el paso más crítico y la fuente del bug de "no aparecen los jugadores". Emitir este evento es obligatorio nada más conectarse. Sin él, el jugador no queda registrado en Redis y su nombre no aparece en la lista del resto de participantes.

      socket.on('connect', () => {
  // ✅ Emitir SIEMPRE al conectarse a la pantalla del lobby
  socket.emit('client:lobby:join');
});

      Respuesta del servidor

      → 1.server:lobby:player_joined a toda la sala:

      // server:lobby:player_joined
{
user: socket.user?.username,
message: `${socket.user?.username} se ha unido a la sala.`,

}

      → 2.server:lobby:state_updated a toda la sala:

      // server:lobby:state_updated
{
  lobbyCode: string;    // "ABCD"
  hostId: string;       // "u_1"
  name: string;         // "Partida de prueba"
  maxPlayers: number;   // 6
  engine: 'STANDARD' | 'STELLA';
  isPrivate: boolean;
  status: 'waiting' | 'playing';
  players: string[];    // ["u_1", "u_2", ...] — IDs de los jugadores
}
      socket.on('server:lobby:state_updated', (lobby) => {
  renderPlayerList(lobby.players);
  // Mostrar botón "Iniciar" solo si eres el host y hay ≥ 4 jugadores
  if (lobby.hostId === myUserId && lobby.players.length >= 4) {
    showStartButton();
  }
});

      3.2 Salir del Lobby — client:lobby:leave

      Para abandonar voluntariamente la sala (el usuario pulsa "Salir"):

      socket.emit('client:lobby:leave');

      No tiene payload. El servidor actualiza Redis y avisa al resto de la sala mediante:

      Respuesta del servidor

      → 1.server:lobby:player_left a toda la sala:

      // server:lobby:player_left
{
user: socket.user?.username,
message: `${socket.user?.username} ha abandonado la sala.`,

}

      → 2.server:lobby:state_updated a toda la sala (estructura del mensaje explicada en 3.2)

      3.3 Iniciar Partida — client:lobby:start

      Solo lo puede emitir el host. Validaciones del servidor:

      • El emisor debe ser el hostId del lobby.
      • Mínimo 4 jugadores conectados.
      socket.emit('client:lobby:start');
// Opcionalmente, permite usar un mazo predefinido en lugar del dinámico:
socket.emit('client:lobby:start', { useDynamicPool: false });

      Respuestas del servidor (éxito):

      // 1. A toda la sala — señal de navegación al tablero (evento legacy)
socket.on('game:started', ({ lobbyCode }) => {
  // Solo indica que hay que navegar; no contiene estado.
  navigateToGameBoard(lobbyCode);
});

// 2. A toda la sala — estado completo inicial de la partida
socket.on('server:game:started', ({ state, message }) => {
  // state = PublicGameState (ver sección 4)
  renderInitialGameState(state);
});

// 3. Solo a este jugador — su mano privada de cartas
socket.on('server:game:private_hand', ({ hand }) => {
  // hand = number[] — IDs de las cartas de este jugador
  renderMyHand(hand);
});

      Warning

      Los tres eventos (game:started, server:game:started y server:game:private_hand) llegan prácticamente a la vez y en orden indeterminado. El código debe manejar los tres de forma independiente. Usa game:started para disparar la navegación y server:game:started + server:game:private_hand para pintar el estado inicial.

      4. Partida (Game)

      4.1 Estado Público del Juego (PublicGameState)

      El estado que llega en server:game:started y server:game:state_updated tiene este formato:

      // Modo STANDARD (Dixit)
interface PublicGameState {
  lobbyCode: string;
  mode: 'STANDARD';
  phase: 'STORYTELLING' | 'SUBMISSION' | 'VOTING' | 'SCORING' | 'FINISHED';
  status: 'playing' | 'finished';
  players: string[]; // ["u_1", "u_2", ...]
  disconnectedPlayers: string[];
  winners?: string[];
  scores: Record<string, number>; // { "u_1": 12, "u_2": 7 }
  currentRound: {
    storytellerId: string;
    clue: string | null;
    storytellerCardId: number | null;
    playedCards: Record<string, number>; // { "u_1": 42 }  — visible solo en VOTING/SCORING
    boardCards: number[]; // Cartas mezcladas visibles en tablero
    votes: Array<{ voterId: string; targetCardId: number }>;
  };
  isStarActive: boolean;
  starExpiresAt: number; // Unix timestamp en ms
  boardRegistry: Record<number, string[]>; // Historial de casillas activadas
  activeModifiers: Record<
    string,
    { type: 'HAND_LIMIT'; value: number; turnsLeft: number }
  >;
  // ⚠️ hands, centralDeck y discardPile NO están incluidos (son privados)
}

// Modo STELLA
interface PublicGameStateStella {
  lobbyCode: string;
  mode: 'STELLA';
  phase:
    | 'STELLA_WORD_REVEAL'
    | 'STELLA_MARKING'
    | 'STELLA_REVEAL'
    | 'SCORING'
    | 'FINISHED';
  status: 'playing' | 'finished';
  players: string[];
  disconnectedPlayers: string[];
  scores: Record<string, number>;
  currentRound: {
    word: string | null;
    boardCards: number[]; // Siempre 15 cartas
    playerMarks: Record<string, number[]>;
    revealedCards: number[];
    currentScoutId: string | null;
    fallenPlayers: string[];
    inTheDarkPlayerId: string | null;
    roundScores: Record<string, number>;
    successfulMarks: Record<string, number>;
  };
}

      Note

      hands, centralDeck y discardPile nunca están en el estado público. La mano propia solo llega por server:game:private_hand en el canal privado del jugador.

      4.2 Canal Principal de Acciones — client:game:action

      Todas las acciones del juego se envían por un único evento. El campo actionType actúa como discriminador:

      socket.emit('client:game:action', {
  lobbyCode: string;      // "ABCD"
  actionType: string;     // Ver tabla abajo
  payload?: object;       // Datos específicos según actionType
});

      Tabla de acciones:

      actionType Fase requerida payload Quién puede emitir
      SEND_STORY STORYTELLING { cardId: number, clue: string } Solo el Storyteller
      SUBMIT_CARD SUBMISSION { cardId: number } Cualquier no-Storyteller
      CAST_VOTE VOTING { cardId: number } Cualquier no-Storyteller
      NEXT_ROUND SCORING (ninguno) Cualquier jugador
      RESOLVE_DUEL Casilla de Duelo { targetId: string } El jugador que cayó en casilla
      CHANGE_MODE Pre-partida { mode: 'STANDARD' | 'STELLA' } Solo el host
      STELLA_SUBMIT_MARKS STELLA_MARKING { cardIds: number[] } Cada jugador
      STELLA_REVEAL_MARK STELLA_REVEAL { cardId: number } El Scout actual (currentScoutId)

      Ejemplos:

      // Storyteller envía su historia
socket.emit('client:game:action', {
  lobbyCode: 'ABCD',
  actionType: 'SEND_STORY',
  payload: { cardId: 42, clue: 'El mar infinito' },
});

// No-Storyteller envía su carta
socket.emit('client:game:action', {
  lobbyCode: 'ABCD',
  actionType: 'SUBMIT_CARD',
  payload: { cardId: 17 },
});

// No-Storyteller vota
socket.emit('client:game:action', {
  lobbyCode: 'ABCD',
  actionType: 'CAST_VOTE',
  payload: { cardId: 17 }, // ← ID de la carta por la que vota, no del jugador
});

      Respuesta tras cualquier acción → server:game:state_updated a toda la sala + server:game:private_hand a cada jugador:

      socket.on('server:game:state_updated', ({ state, lastAction }) => {
  // state = PublicGameState
  // lastAction = string — qué acción causó el cambio (ej: 'SEND_STORY')
  updateGameUI(state);
});

      4.3 Máquina de Estados

      Modo STANDARD:

      STORYTELLING ──(SEND_STORY)──► SUBMISSION ──(SUBMIT_CARD ×todos)──► VOTING
                                                                          │
                     STORYTELLING ◄──(NEXT_ROUND)──── SCORING ◄──(CAST_VOTE ×todos)
                     (nueva ronda)                       │
                                                      FINISHED (si alguien ≥ 42 pts)

      Modo STELLA:

      STELLA_WORD_REVEAL ──► STELLA_MARKING ──(SUBMIT_MARKS ×todos)──► STELLA_REVEAL
                                                                        │
STELLA_WORD_REVEAL ◄──(NEXT_ROUND)──────── SCORING ◄──(REVEAL_MARK ×todos los scouts)
   (nueva ronda)                               │
                                            FINISHED (si alguien ≥ 30 pts)

      Timeouts automáticos (BullMQ):

      Fase Timeout Acción automática del servidor
      STORYTELLING 60 s Juega carta aleatoria por el Storyteller AFK
      SUBMISSION 45 s Juega carta aleatoria por cada no-Storyteller AFK
      VOTING 45 s Vota aleatoriamente por cada jugador AFK
      SCORING 10 s Llama NEXT_ROUND automáticamente

      Tip

      No implementes reintentos ni timers en el frontend. El servidor los gestiona por su cuenta con BullMQ. Solo escucha server:game:state_updated y renderiza.

      4.4 Mano Privada — server:game:private_hand

      Este evento llega en múltiples momentos, no solo al inicio:

      • Al iniciar la partida
      • Al comenzar cada nueva ronda (NEXT_ROUND)
      • Si el jugador cae en casilla Shuffle
      • Al reconectarse a una partida en curso
      // ✅ Actualizar siempre que llegue, sin condicionarlo a ninguna fase
socket.on('server:game:private_hand', ({ hand }) => {
  // hand = number[] — IDs de cartas de este jugador
  myHand = hand;
  renderMyHand(hand);
});

      4.5 Tablero — Casillas Especiales

      Cuando un jugador pisa una casilla especial, llegará server:game:special_event a toda la sala:

      // server:game:special_event
{
  effect: 'ODD' | 'EVEN' | 'EQUILIBRIUM' | 'SHUFFLE' | 'CARD_BONUS' | 'STELLA_BONUS_PLACEHOLDER';
  pId?: string;      // userId del jugador afectado
  points?: number;   // Puntos ganados/perdidos (ODD, EVEN)
  squareId?: number; // Nº de casilla (ODD, EVEN)
  amount?: number;   // Modificador de cartas (CARD_BONUS)
  message?: string;  // Texto descriptivo (STELLA_BONUS_PLACEHOLDER)
}
      socket.on('server:game:special_event', (ev) => {
  switch (ev.effect) {
    case 'ODD':
    case 'EVEN':
      showToast(
        `${ev.pId}: ${ev.points > 0 ? '+' : ''}${ev.points} pts (casilla ${ev.squareId})`,
      );
      break;
    case 'EQUILIBRIUM':
      showToast('¡Equilibrio! Todos avanzan según su ranking');
      break;
    case 'SHUFFLE':
      showToast(`${ev.pId} recibió una nueva mano de cartas`);
      break;
    case 'CARD_BONUS':
      showToast(
        `${ev.pId}: ${ev.amount > 0 ? '+' : ''}${ev.amount} cartas durante 2 rondas`,
      );
      break;
  }
});

      Mapa de casillas especiales:

      Posición Tipo Efecto
      5, 9 IMPAR 1º llegado: +1, 2º: -1, 3º: +2, 4º: -2, ...
      7, 11 PAR 1º: -1, 2º: +1, 3º: -2, 4º: +2, ...
      15, 21, 31, 37 Bonus Aleatorio ±1-3 cartas extra durante 2 rondas
      18, 34 Shuffle Toda la mano descartada y nuevas cartas robadas
      25, 40 Duelo Ver 4.6
      27 Equilibrio ★ Cada jugador +N pts según su posición ranking
      42 META 🏁 phase → FINISHED

      Note

      Las casillas IMPAR/PAR solo tienen efecto la primera vez que cada jugador las pisa. Las siguientes veces se ignoran.

      4.6 Duelo — server:game:duel_available

      Este evento llega solo al jugador que pisó la casilla de duelo (canal privado userId):

      // server:game:duel_available
{
  challengerId: string;
} // El propio userId del jugador
      socket.on('server:game:duel_available', ({ challengerId }) => {
  // Mostrar modal para elegir rival
  showDuelModal(availablePlayers, (selectedTargetId) => {
    socket.emit('client:game:action', {
      lobbyCode: currentLobbyCode,
      actionType: 'RESOLVE_DUEL',
      payload: { targetId: selectedTargetId },
    });
  });
});

      4.7 Estrella Fugaz (Mini-juego)

      Activar estrella (solo el servidor la lanza, pero puede dispararse desde el cliente)

      // Cualquier jugador puede lanzar la estrella
socket.emit('client:game:trigger_star', { lobbyCode: 'ABCD' });

      Aparición de la estrella — star_spawned (a toda la sala)

      {
  starId: string; // "star_1712580000000"
  path: {
    start: {
      x: number;
      y: number;
    } // Coordenadas % de pantalla (0–100)
    end: {
      x: number;
      y: number;
    }
  }
  duration: number; // ms que dura la estrella (2000–4000 ms)
}
      socket.on('star_spawned', ({ path, duration, starId }) => {
  animateStar(path, duration);
  // Mostrar botón clickeable durante `duration` ms
  showClaimButton(starId, duration, () => {
    socket.emit('client:game:claim_star', { lobbyCode: currentLobbyCode });
  });
});

      Estrella reclamada — star_claimed (a toda la sala)

      {
  winnerId: string;
  newScores: Record<string, number>; // Puntuaciones con el +3 ya aplicado
}
      socket.on('star_claimed', ({ winnerId, newScores }) => {
  hideStar();
  showToast(`${winnerId} ganó la estrella (+3 pts)!`);
  updateScoreboard(newScores);
});

      Note

      Si nadie reclama la estrella antes de que expire duration, desaparece automáticamente (el servidor la desactiva). No hace falta manejar un timer en el frontend; simplemente esconder el elemento al expirar el tiempo de la animación.

      4.8 Mazo Rebarajado — server:game:deck_reshuffled

      El mazo central se agotó y los descartes se reciclaron:

      socket.on('server:game:deck_reshuffled', () => {
  // Mostrar animación visual: el descarte vuelve al mazo central
  animateDeckReshuffle();
});

      4.9 Fin de Partida — client:game:end / server:game:ended / server:economy:wallet_updated

      Cuando la partida llega a su fin (la fase pasa a FINISHED), el propio backend se encarga de finalizar la partida, no obstante (y de momento), la partida también puede ser finalizada desde el frontend mediante el evento de cierre client:game:end para que el servidor calcule el ranking y reparta las monedas.

      Emitir cierre de partida

      // Enviar cuando phase === 'FINISHED' en el estado del juego
socket.emit('client:game:end', { lobbyCode: 'ABCD' });

      Important

      Solo es necesario que un jugador (generalmente el host, o el que detecte phase === 'FINISHED') emita este evento. El servidor aplica la lógica una única vez.

      Pese a que el evento client:game:end otorgue el poder al frontend de finalizar la partida en cualquier momento, la partida se finaliza automáticamente si se llegua al final de ella. Esto es, mediante el siguiente flujo:

      (Frontend) -- `client:game:action` --> (game.handler) --- handleAction() --> (game.service) -- transition() --> (engine)

(Frontend) <-- `server:game:ended` --- (game.handler) <-- finalizeGame() -- (game.service) <-- newState(END) -- (engine)

      Por ende, lo que queda de apartado corresponde a lo que ocurre cuando termina la partida independientemente si se acaba por su flujo natural, o por orden del frontend.

      Resultado global — server:game:ended (a toda la sala)

      // server:game:ended
{
  ranking: Array<{
    playerId: string;    // "u_1"
    points: number;      // Puntuación final en la partida
    place: number;       // 1 = ganador
    coinsEarned: number; // Monedas ganadas según el puesto
  }>;
  error?: string;        // Solo presente si falló al guardar estadísticas en BD
}
      socket.on('server:game:ended', ({ ranking }) => {
  // ranking está ordenado de mayor a menor puntuación
  showResultsScreen(ranking);

  // Ejemplo:
  // ranking[0] → ganador, ranking[ranking.length - 1] → último
});

      Tabla de recompensas según puesto:

      Puesto Monedas ganadas
      1º 50
      2º 35
      3º 25
      4º 15
      5º+ 10 (por defecto)

      Saldo actualizado — server:economy:wallet_updated (solo a ese jugador)

      Justo después de server:game:ended, cada jugador recibe en su canal privado (userId) su nuevo saldo de monedas:

      // server:economy:wallet_updated
{
  balance: number; // Saldo total actualizado (no solo las ganadas, sino el total)
}
      socket.on('server:economy:wallet_updated', ({ balance }) => {
  // Actualizar el widget de monedero en la UI en tiempo real
  updateWalletWidget(balance);
});

      Note

      balance es el saldo total del usuario tras sumar las monedas ganadas, no solo el incremento. Los resultados se persistieron atómicamente en la base de datos antes de emitir este evento.

      4.10 Minijuego — server:game:minigame_start

      Cuando dos jugadores entran en un duelo, este evento se emite a los dos participantes para mostrar el minijuego, y al resto de la sala para mostrar un cartel de "Duelo en curso":

      // server:game:minigame_start
{
  player1: string; // userId del primer jugador
  player2: string; // userId del segundo jugador
  type: number; // Tipo de minijuego
  duration: number; // Duración en ms
  isDuel: boolean; // true cuando es un duelo de casilla
}
      socket.on(
  'server:game:minigame_start',
  ({ player1, player2, type, duration, isDuel }) => {
    const myId = getCurrentUserId();
    if (myId === player1 || myId === player2) {
      // Mostrar interfaz del minijuego para el jugador participante
      showMinigameUI({ player1, player2, type, duration });
    } else {
      // Mostrar indicador de "Duelo en curso" al resto
      showDuelInProgress(player1, player2);
    }
  },
);

      4.11 Errores de Juego — server:game:error

      Distinto de server:error (validación general), este evento es específico de la lógica del juego. Se recibe cuando un jugador intenta realizar una acción ilegal durante el juego (p.ej. jugar una carta en un momento no permitido):

      // server:game:error
{
  message: string; // Descripción del error
}
      socket.on('server:game:error', ({ message }) => {
  showInGameErrorToast(message);
});

      5. Chat

      Enviar mensaje — client:chat:send 

      socket.emit('client:chat:send', {
  lobbyCode: string;  // 4 caracteres exactos
  text: string;       // Min 1, Max 255 caracteres
});

      Recibir mensaje — server:chat:message_received (a toda la sala)

      {
  username: string;
  text: string;
  timestamp: string; // ISO 8601 — ej: "2025-04-09T16:00:00.000Z"
}
      socket.on('server:chat:message_received', ({ username, text, timestamp }) => {
  appendChatMessage({ username, text, timestamp });
});

      6. Reconexión y Sesión

      El sistema distingue dos escenarios de desconexión: mientras se está en el lobby (sala de espera) o durante una partida en curso. La reconexión es automática al volver a conectar con el mismo wsToken válido; el servidor detecta el estado y envía el evento de recuperación apropiado sin necesidad de que el frontend emita nada adicional.

      6.1 Desconexión desde el Lobby

      El backend saca al usuario del lobby en Redis al desconectarse y notifica al resto mediante dos eventos:

      → 1. server:lobby:player_left (al resto de jugadores de la sala):

      {
  // server:lobby:player_left
  user: string; // username del jugador desconectado
  message: string; // "<username> se ha desconectado de la sala."
}

      → 2. server:lobby:state_updated (a toda la sala): estado actualizado sin el jugador.

      6.2 Reconexión al Lobby

      Tras reconectarse con el mismo wsToken, el servidor emite automáticamente tres eventos:

      → 1. server:lobby:recovered (solo al jugador reconectado):

      // server:lobby:recovered — Solo lo recibe el jugador que se reconectó
{
  lobbyCode: string;
  lobby: LobbyState; // Estado actual del lobby (con el jugador ya incluido)
}
      socket.on('server:lobby:recovered', ({ lobbyCode, lobby }) => {
  // Mostrar directamente la sala de espera con el estado actual
  navigateToLobby(lobbyCode, lobby);
  // ¡NO es necesario emitir client:lobby:join después — el servidor ya re-añadió al jugador!
});

      → 2. server:lobby:player_reconnected (al resto de la sala):

      // server:lobby:player_reconnected — Lo reciben los DEMÁS jugadores
{
  user: string; // username del jugador reconectado
  message: string; // "<username> se ha reconectado a la sala."
}

      → 3. server:lobby:state_updated (a toda la sala, incluido el reconectado): estado completo con el jugador ya reincorporado.

      6.3 Desconexión durante Partida

      Si un jugador se desconecta mientras hay una partida en curso, no se le saca de Redis. El estado de la partida se conserva íntegro. Los demás jugadores no reciben ninguna notificación automática — la desconexión durante partida no interrumpe el flujo de juego.

      Note

      El jugador desconectado durante una partida puede aparecer en disconnectedPlayers del PublicGameState la próxima vez que el estado se actualice. El frontend puede usar este campo para mostrar un indicador visual en la ficha del jugador.

      6.4 Reconexión a Partida en Curso — server:session:recovered

      Si al reconectarse el servidor detecta una partida activa para ese lobbyCode, envía directamente el estado del tablero:

      // server:session:recovered — Solo al jugador reconectado
{
  lobbyCode: string;
  state: PublicGameState; // Estado actual de la partida (sin hands ni centralDeck)
}
      socket.on('server:session:recovered', ({ lobbyCode, state }) => {
  // Navegar directamente al tablero sin pasar por el lobby
  navigateToGameBoard(lobbyCode, state);
  // Inmediatamente después llegará server:game:private_hand con la mano actual
});

      7. Errores y Casos Límite

      Errores del servidor — server:error 

      {
  message: string;
  code?: string;
}
      // ✅ Registrar SIEMPRE este listener
socket.on('server:error', ({ message }) => {
  showErrorToast(message);
});

      Errores comunes que puede devolver el servidor:

      Mensaje Causa
      "Autenticación denegada: wsToken ausente" No se pasó token en el handshake
      "Autenticación denegada: Ticket inválido o expirado" Token caducado (5 min) o firmado incorrectamente
      "Solo el líder puede empezar la partida." client:lobby:start enviado por un no-host
      "Se requieren al menos 4 jugadores para iniciar." Menos de 4 jugadores en el lobby
      "La sala no existe o ha expirado." El lobby no está en Redis
      "Partida no encontrada o expirada." El estado de la partida no está en Redis
      "Formato de acción inválido" El payload de client:game:action no es válido
      "Formato de mensaje inválido" El texto del chat no cumple validación Zod

      Conexión forzada por multipestaña — server:force_disconnect

      Si el mismo usuario abre el juego en otra pestaña, el servidor desconecta la sesión antigua:

      {
  message: string;
}
      // ✅ Registrar ANTES de cualquier otra lógica
socket.on('server:force_disconnect', ({ message }) => {
  alert(message); // "Has abierto el juego en otra pestaña..."
  socket.disconnect();
  redirectToHome();
});

      Errores de conexión

      socket.on('connect_error', (error) => {
  // error.message = "Autenticación denegada: ..."
  console.error('Error de conexión:', error.message);
  // Redirigir al login si el token expiró
});

      8. Referencia Rápida de Eventos

      Cliente → Servidor (Eventos que emite el Frontend)

      Evento Cuándo Payload
      client:lobby:join Al entrar a la pantalla del lobby (ninguno)
      client:lobby:leave Al pulsar "Salir" del lobby (ninguno)
      client:lobby:start Host pulsa "Iniciar Partida" { useDynamicPool?: boolean }
      client:game:action Cualquier acción de juego { lobbyCode, actionType, payload? }
      client:game:end Fase llega a FINISHED { lobbyCode }
      client:game:trigger_star Lanzar estrella fugaz { lobbyCode }
      client:game:claim_star Pulsar la estrella { lobbyCode }
      client:chat:send Enviar mensaje al chat { lobbyCode, text }

      Servidor → Cliente (Eventos que escucha el Frontend)

      Evento Destino Cuándo llega
      server:lobby:state_updated Toda la sala Alguien entra o sale del lobby
      server:lobby:player_joined Toda la sala Un jugador se une al lobby
      server:lobby:player_left Toda la sala Un jugador sale o se desconecta del lobby
      server:lobby:player_reconnected Toda la sala Un jugador se reconecta al lobby
      game:started Toda la sala Señal legacy: navegar al tablero
      server:game:started Toda la sala La partida arranca (con estado completo)
      server:game:state_updated Toda la sala Cualquier acción de juego cambia el estado
      server:game:ended Toda la sala La partida termina: ranking final y monedas
      server:game:private_hand Solo ese jugador Inicio, nueva ronda, shuffle o reconexión
      server:game:special_event Toda la sala Alguien pisa una casilla especial
      server:game:duel_available Solo el retador El jugador pisa casilla de duelo
      server:game:minigame_start Duelo activo Comienza un minijuego de duelo
      server:game:deck_reshuffled Toda la sala El mazo central se rebarajó
      server:game:error Solo ese jugador Acción ilegal dentro de la partida
      server:economy:wallet_updated Solo ese jugador Saldo de monedas actualizado tras fin de partida
      star_spawned Toda la sala Aparece una estrella fugaz
      star_claimed Toda la sala Alguien reclamó la estrella
      server:chat:message_received Toda la sala Nuevo mensaje de chat
      server:session:recovered Solo ese jugador Reconexión a partida en curso
      server:lobby:recovered Solo ese jugador Reconexión a lobby en espera
      server:force_disconnect Solo ese jugador Multipestaña detectada
      server:error Solo ese jugador Error de validación o negocio

      9. Checklist de Integración

      ✅ Obtener wsToken del endpoint HTTP antes de conectar
✅ Pasar el token en auth.token (NO en headers)
✅ Registrar server:force_disconnect ANTES de cualquier otra lógica
✅ Emitir client:lobby:join nada más conectarse a la pantalla del lobby
✅ Escuchar server:game:private_hand en CUALQUIER fase (se actualiza sin aviso previo)
✅ Usar server:game:state_updated para detectar la fase y renderizar la UI
✅ Mostrar botón "Iniciar" solo si lobby.players.length >= 4 Y userId === hostId
✅ Escuchar server:session:recovered y server:lobby:recovered para reconexiones
✅ Manejar star_spawned / star_claimed para el mini-juego Estrella Fugaz
✅ No usar socket.id como identificador — usar siempre el userId del JWT (u_123)
✅ No implementar timers de timeout de fase — el servidor los gestiona automáticamente
✅ Siempre escuchar server:error Y server:game:error para mostrar mensajes de error
✅ Emitir client:game:end cuando phase === 'FINISHED' para cerrar la partida
✅ Escuchar server:game:ended para mostrar la pantalla de resultados con el ranking
✅ Escuchar server:economy:wallet_updated para actualizar el saldo de monedas en tiempo real
✅ NO emitir client:lobby:join tras server:lobby:recovered — el servidor ya re-añadió al jugador

      Notas Adicionales

      • Un único namespace: Solo se usa el namespace por defecto (/). No hay namespaces separados para lobby, juego o chat.
      • IDs de usuario: Siempre en formato "u_123" (prefijo u_ + id numérico). Nunca usar socket.id para identificar jugadores.
      • Orden de eventos: server:game:started y server:game:private_hand pueden llegar en cualquier orden al inicio de partida. Diseñar el código para manejar ambos de forma independiente.
      • Reconexión transparente: Al perder conexión (F5, red caída), simplemente volver a conectar con el mismo wsToken válido. El servidor devuelve el estado automáticamente sin necesidad de volver a emitir nada.
